## 1. 设计原则（后续改动共用）

1. **一把门把手**：低频破坏性操作默认隐形，hover/focus 才出现；出现时用胶囊承载，不改变行高与布局。
2. **一套控件语言**：控件高度 30px（小号 26px）、圆角 8px（胶囊 10px/16px）、图标 16px、间距 6/8/12 三档；五套主题只换 token，不换结构。
3. **一条阅读中线**：消息、输入卡、附件共用 `--content-max`；侧栏只做信息，不抢阅读宽度。
4. **颜色只来自 token**：组件里不写死 hex；所有状态色走 `--accent / --ok / --warn / --danger`。
5. **动效可关**：所有过渡在 `prefers-reduced-motion` 下归零；不因动效改变布局。

## 2. 待办需求总表

### P0 — 可读性与可访问性

#### V1. Markdown 段落与真实列表渲染 🟡

**问题**
- 助理气泡目前把多行文本按 `pre-wrap` 输出，数字/项目符号列表只是「看起来像列表」，没有 `ul/ol/li` 语义、缩进与层级。
- 段落之间没有间距节奏，长回复是一整块文字。

**方案**
- `src/renderer/markdown.ts` 的块级解析补齐：段落、`ul/ol`（含嵌套）、`blockquote`、`hr`、任务列表 `- [ ]`。
- 列表样式使用主题 token：marker 用 `--text-dim`，嵌套缩进 18px，行距 1.65。
- 代码块、表格、引用与列表混排时保持 8px 块间距。

**验收**
- 一段包含三级嵌套列表 + 引用 + 代码块的回复，DOM 为真实的 `ul/ol/li/blockquote`。
- 五套主题下 marker 与正文对比度 ≥ 4.5:1（正文）/ 3:1（marker）。
- 新增 `test/markdown-lists.test.mjs`（node --test，纯函数输入输出）。

#### V2. 气泡内标题层级与排版节奏 🟡

**问题**
- `h1–h6` 继承浏览器默认尺寸，在 14px 气泡里过大；标题与上下文的间距不一致。

**方案**
- 气泡内标题降级为 15/14/13px 三档，字重 600，`margin: 12px 0 6px`；首个子元素 `margin-top: 0`，末个子元素 `margin-bottom: 0`。
- 段落 `margin: 0 0 8px`；连续列表与段落之间 8px。
- 链接使用 `--accent` + 下划线偏移 2px。

**验收**
- 含 h1/h2/h3、段落、列表、代码的混合回复在 1440 与 980 宽度下无溢出、无贴边。
- 气泡首尾无多余空白。

#### V3. 对比度与键盘可达性 🟡

**问题**
- `--text-dim` 在 warm / light 主题的部分表面上低于 4.5:1；会话操作胶囊依赖 hover，纯键盘用户需要 `focus-within` 才可见（已实现，但缺少完整焦点环）。
- 模态、tab、分页器等仍有部分元素无 `:focus-visible` 样式。

**方案**
- 统一 `--focus-ring: color-mix(in srgb, var(--accent) 55%, transparent)`，所有可交互元素 `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; }`。
- 逐主题微调 `--text-dim`：目标正文 4.5:1、次要文本 ≥ 3:1。
- 会话列表补充 `role="option"` / `aria-selected`，支持 ↑/↓ 切换、Enter 打开、F2 重命名、Delete 删除（带确认）。

**验收**
- 用对比度脚本（或人工抽查）验证 5 主题的主要文本对：正文/次要/按钮文字。
- Tab 键可走完：工具栏 → 会话列表 → 会话操作 → tab 栏 → 输入区 → 侧栏。
- 新增 `test/a11y-static.test.mjs`：扫描 `static/index.html` 的交互元素是否都有可访问名称。

#### V4. 窄屏侧栏覆盖层收尾 🟡

**问题**
- < 1240px 手动展开右侧栏、< 1040px 手动展开左侧栏时，面板直接覆盖聊天区，没有遮罩、点击外部或 Esc 关闭。

**方案**
- 覆盖模式下加 `backdrop`（`color-mix(in srgb, #000 32%, transparent)` + 轻微 blur），点击遮罩或 Esc 关闭并恢复自动收起状态。
- 面板进入用 160ms `translateX`，`prefers-reduced-motion` 下取消。
- 不改变已保存的展开/收起偏好。

**验收**
- 1100px 下手动展开右栏：出现遮罩，点击遮罩/Esc 关闭，聊天区不被永久压缩。
- 1240px 边界不再出现「刚好 1240 时右栏覆盖聊天」的问题（本轮已把 CSS 断点改为 1239/1039，与 JS 对齐）。

### P1 — 信息架构与日常效率

#### V5. 右侧栏分组卡片化 🟡

**问题**
- 11 行平铺的 `info-grid` 信息密度高但层级弱：资源、会话、任务、文件四类信息视觉权重相同。
- 低频字段（语音模型、视觉模型、压缩统计）长期占用首屏。

**方案**
- 拆为 4 张卡：**运行状态**（资源、RPM、MCP）、**会话**（Provider/Model/权限/Token/目录）、**任务进展**、**文件**。
- 卡片头部可折叠，状态记忆到 `localStorage`；默认只展开「运行状态 + 任务」。
- 低频字段收进会话卡的「更多信息」折叠区。
- 卡片间距 10px、内边距 10px，标题 11px 大写 + letter-spacing。

**验收**
- 首屏只保留 5–7 行关键信息；展开/折叠有过渡且不跳动。
- 274px 与 250px 宽度下不出现横向滚动。

#### V6. 资源读数简化与状态化 🟡

**问题**
- 「内存 418 MB · CPU 6.2% · 正常」一行文字在窄侧栏容易换行，且没有趋势感。

**方案**
- 改为两行紧凑读数：`内存 418 MB` / `CPU 6.2%`，右侧一个状态点（normal/warning/overloaded 三色）。
- 数值使用 tabular-nums；超过阈值时状态点呼吸但遵守 reduced-motion。
- 与排期文档中的 G1（上下文进度条 + TPS）共用视觉语言，避免两套读数风格。

**验收**
- 250px 宽度不换行；状态点颜色与 `--ok/--warn/--danger` 一致。
- 阈值行为与原 `rside-rpm-*` 保持一致。

#### V7. 冻结按钮迁移 🟡

**问题**
- 冻结视图浮在消息区右上角，遮挡内容；与 tab 栏、消息滚动条竞争同一角落。

**方案**
- 移入 tab 栏右侧或输入区 action bar 左侧，作为常驻 toggle chip（雪花图标 + 文案，激活时 accent 描边）。
- 保留 `Ctrl+.` 快捷键与 `aria-pressed`；会话切换时行为不变。

**验收**
- 消息区右上角不再有浮动按钮；1440/980 下均不遮挡首条消息。
- 快捷键与 tooltip 仍可用。

#### V8. 工具卡与思考块密度 🟡

**问题**
- `tool-card` 左内边距、等宽字体与结果区在长输出时显得笨重；思考块展开后与正文的层级不够清楚。

**方案**
- 头部高度 28px，名称 12px 600，参数右对齐省略；结果区最大高度 160px + 渐隐遮罩。
- 折叠状态持久化到会话内（内存即可），重新渲染不回到展开。
- 思考块使用虚线左边框 + `--text-dim`，默认折叠。

**验收**
- 连续 5 个工具卡不产生超过 60% 视口的占位；展开/折叠状态在流式更新中保持。

#### V9. 中英文标签统一 🟡

**问题**
- 中文界面里仍有 `Provider / Model / RPM` 等英文标签，与「会话信息」等中文标题混排。

**方案**
- 统一为「服务商 / 模型 / 每分钟请求」；专有名词（MCP、Token）保留英文。
- 通过 i18n 字典新增键，不在模板里写死。

**验收**
- `npm run check:i18n` 通过；切换 en 后无中文残留。

### P2 — 观感打磨

#### V10. 主题 token 体系 🟡

**问题**
- 现有 token 只有颜色，缺少表面层级、阴影、焦点环、代码块、选中态；组件里仍有 `rgba(255,255,255,0.04)` 这类硬编码。

**方案**
- 新增语义 token：`--surface-1/2/3`、`--text-strong/muted/faint`、`--shadow-1/2`、`--focus-ring`、`--selection-bg`、`--code-border`。
- 五套主题各给一份完整映射；组件逐步替换硬编码。
- 设置里增加主题色板预览（5 个小色块），便于用户选择。

**验收**
- `rg "rgba\\(255, 255, 255|#[0-9a-fA-F]{6}" static/styles.css` 在组件区（非主题定义区）降到 0。
- 五套主题切换无闪烁、无对比度回归。

#### V11. FX / 玻璃拟态按主题分档 🟡

**问题**
- 粒子背景与 backdrop-filter 在所有主题下强度相同；light/cartoon 下玻璃层可能显得脏，低端机有开销。

**方案**
- 每主题定义 `--fx-opacity`、`--glass-blur`、`--glass-saturate`；light/cartoon 降低粒子与模糊，tech 增强。
- 窗口失焦 / 电池模式 / `prefers-reduced-motion` 时暂停粒子。
- 设置项「动态背景」三档：关闭 / 轻柔 / 完整。

**验收**
- 关闭动态背景后 CPU 占用明显下降；light 主题的输入卡不再出现灰蒙层。
- 所有玻璃层在无 `backdrop-filter` 支持时降级为不透明表面。

#### V12. 滚动条与滚动阴影 🟡

**问题**
- 消息区滚动条 20px 宽（为可点击优化），视觉偏重；侧栏滚动条样式不统一。

**方案**
- 统一 10px overlay 滚动条，hover 时加深；`scrollbar-width: thin` 兼容 Firefox。
- 消息区顶部/底部加 12px 渐隐阴影，提示可滚动。

**验收**
- 1440/980 下滚动条不遮挡内容；顶部渐隐在滚动到顶时消失。

#### V13. 动效与状态过渡 🟡

**问题**
- 侧栏宽度、会话胶囊、MCP chip、主题切换的时长/曲线不一致。

**方案**
- 统一 160ms `cubic-bezier(0.2, 0.8, 0.2, 1)`；只在 transform/opacity/background 上做动画。
- `prefers-reduced-motion` 全部归零；不做高度动画避免抖动。

**验收**
- 连续快速 hover 会话行无残影；主题切换无布局位移。

#### V14. 空状态与首次使用 🟡

**问题**
- 空会话只显示一行提示；没有引导用户「打开项目 / 新建会话 / 输入第一条消息」。

**方案**
- 空状态改为一张轻量卡片：标题 + 3 个快捷动作（打开项目、新建会话、查看快捷键）。
- 首次 hover 会话行时，胶囊出现一次 1.2s 的微光提示（仅一次，存 localStorage）。

**验收**
- 新用户能在空状态直接完成「打开项目 → 发第一条消息」。
- 微光提示不重复打扰。

### P3 — 可选增强

#### V15. 自定义标题栏 ⚪

**问题**

**验收**

- 不改变现有隐藏式设计。

**验收**
- 键盘用户无需鼠标即可完成 pin/rename/delete。

## 4. 工程约定

1. **零新增运行时依赖**：本轮及后续视觉改动只用 CSS + 原生 DOM；图标继续走 `icons.ts`。
2. **字符串全部走 i18n**：新增文案必须同时补 `zh-CN` / `en`，提交前跑 `npm run check:i18n`。
3. **测试**：纯函数（markdown 解析、token 映射）用 `node --test`；DOM 结构用静态扫描测试；不引入浏览器测试框架。
4. **断点单一来源**：JS 自动收起阈值与 CSS 覆盖断点必须成对维护（当前 JS `< 1240 / < 1040`，CSS `max-width: 1239 / 1039`）。
5. **阅读宽度单一来源**：`--content-max` 只在一处定义，消息区与输入区共用。
6. **可访问性门槛**：任何新增交互元素必须有可访问名称、`:focus-visible` 样式、键盘路径；破坏性操作必须二次确认。
7. **视觉验收**：每个 Sprint 结束用隔离数据目录启动真机窗口截图；静态预览仅用于快速迭代。
